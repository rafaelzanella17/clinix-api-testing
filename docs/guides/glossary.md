# Glossário - Termos Técnicos

## A

**API (Application Programming Interface)**
Interface de programação que permite comunicação entre diferentes sistemas através de endpoints HTTP.

**Assertion**
Declaração que verifica se uma condição específica é verdadeira durante a execução de um teste.

**Authentication**
Processo de verificação da identidade de um usuário através de credenciais (email/senha).

**Authorization**
Processo de verificação se um usuário autenticado tem permissão para acessar um recurso específico.

**Automated Testing**
Execução de testes através de scripts e ferramentas, sem intervenção manual.

---

## B

**Boundary Testing**
Técnica que testa os limites ou fronteiras dos valores de entrada de um sistema.

**Bug**
Defeito ou erro no software que causa comportamento inesperado ou incorreto.

**Bug Report**
Documento que descreve detalhadamente um defeito encontrado, incluindo passos para reprodução.

---

## C

**CRUD**
Acrônimo para Create, Read, Update, Delete - operações básicas em dados.

**CI/CD (Continuous Integration/Continuous Deployment)**
Práticas de integração contínua e deploy automatizado.

**Coverage (Cobertura)**
Métrica que indica a porcentagem do código ou funcionalidades testadas.

**CPF (Cadastro de Pessoas Físicas)**
Documento brasileiro de identificação fiscal, validado por algoritmo específico.

**Chai**
Biblioteca JavaScript de asserções para testes, usada com Mocha.

---

## D

**Dashboard**
Interface visual que apresenta métricas, KPIs e informações de forma organizada.

**Database (Banco de Dados)**
Sistema de armazenamento estruturado de dados, no projeto usa PostgreSQL.

**Debugging**
Processo de identificação e correção de erros no código ou testes.

---

## E

**Endpoint**
URL específica de uma API que aceita requisições e retorna responses.

**End-to-End Testing (E2E)**
Testes que validam fluxos completos do usuário, do início ao fim.

**Environment (Ambiente)**
Configuração específica onde os testes são executados (test, staging, prod).

**ESLint**
Ferramenta de análise estática que identifica problemas no código JavaScript.

---

## F

**Functional Testing**
Testes que validam se o sistema atende aos requisitos funcionais especificados.

**Faker**
Biblioteca que gera dados falsos realistas para uso em testes.

---

## G

**GET**
Método HTTP usado para recuperar dados de um servidor.

**Git**
Sistema de controle de versão distribuído usado para gerenciar código fonte.

---

## H

**HTTP Status Codes**
Códigos numéricos que indicam o resultado de uma requisição HTTP (200, 401, 404, etc.).

**Health Check**
Verificação básica para confirmar se um sistema está funcionando corretamente.

**Husky**
Ferramenta que permite executar scripts em eventos do Git (hooks).

---

## I

**Integration Testing**
Testes que verificam a comunicação entre diferentes módulos ou sistemas.

**ISTQB (International Software Testing Qualifications Board)**
Organização que define padrões e certificações para testes de software.

**ISO/IEC 25010:2023**
Norma internacional que define modelo de qualidade de software.

---

## J

**JWT (JSON Web Token)**
Padrão para criação de tokens de acesso seguros baseados em JSON.

**JSON (JavaScript Object Notation)**
Formato de dados leve usado para troca de informações entre sistemas.

---

## K

**k6**
Ferramenta de código aberto para testes de performance e carga.

**KPI (Key Performance Indicator)**
Indicador-chave de performance usado para medir sucesso de objetivos.

---

## L

**Load Testing**
Teste que avalia o comportamento do sistema sob carga normal de usuários.

**LGPD (Lei Geral de Proteção de Dados)**
Lei brasileira que regula o tratamento de dados pessoais.

---

## M

**Mocha**
Framework de testes JavaScript usado para estruturar e executar testes automatizados.

**Mochawesome**
Reporter para Mocha que gera relatórios HTML visuais dos resultados dos testes.

**Mock**
Objeto falso que simula o comportamento de componentes reais durante os testes.

**Middleware**
Software que atua como intermediário entre diferentes aplicações ou componentes.

---

## N

**Non-Functional Testing**
Testes que validam aspectos como performance, segurança, usabilidade, etc.

**NPM (Node Package Manager)**
Gerenciador de pacotes para Node.js usado para instalar dependências.

**Negative Testing**
Técnica que testa o sistema com dados inválidos ou cenários de erro.

---

## O

**OWASP (Open Web Application Security Project)**
Organização que define padrões de segurança para aplicações web.

**OAuth**
Protocolo de autorização que permite acesso seguro a recursos.

---

## P

**POST**
Método HTTP usado para enviar dados para criar novos recursos no servidor.

**PUT**
Método HTTP usado para atualizar recursos existentes no servidor.

**Performance Testing**
Testes que medem tempos de resposta, throughput e uso de recursos.

**PostgreSQL**
Sistema de gerenciamento de banco de dados relacional usado no projeto.

**Postman**
Ferramenta para testar APIs através de interface gráfica.

**Positive Testing**
Técnica que testa o sistema com dados válidos e cenários esperados.

---

## Q

**QA (Quality Assurance)**
Processo sistemático para garantir que um produto atende aos padrões de qualidade.

**Query**
Consulta feita a um banco de dados para recuperar, inserir, atualizar ou deletar dados.

---

## R

**REST (Representational State Transfer)**
Estilo arquitetural para APIs baseado em HTTP e operações CRUD.

**Regression Testing**
Re-execução de testes para verificar se mudanças não introduziram novos defeitos.

**Response Time**
Tempo que um sistema leva para responder a uma requisição.

**Role-Based Access Control (RBAC)**
Sistema de controle de acesso baseado em papéis/perfis de usuário.

**Rate Limiting**
Técnica para limitar o número de requisições por usuário em um período.

---

## S

**Smoke Testing**
Conjunto básico de testes para verificar se as funcionalidades críticas funcionam.

**Stress Testing**
Teste que avalia o comportamento do sistema sob carga extrema.

**Supertest**
Biblioteca JavaScript para testar APIs HTTP de forma programática.

**SLA (Service Level Agreement)**
Acordo que define níveis mínimos de qualidade de serviço.

**SQL Injection**
Vulnerabilidade de segurança que permite execução de comandos SQL maliciosos.

**Schema Validation**
Verificação se a estrutura dos dados está conforme o formato esperado.

---

## T

**TDD (Test-Driven Development)**
Metodologia onde testes são escritos antes do código de produção.

**Test Case**
Conjunto de condições e passos para verificar uma funcionalidade específica.

**Test Data**
Dados específicos usados durante a execução dos testes.

**Test Suite**
Coleção de casos de teste agrupados por funcionalidade ou módulo.

**Throughput**
Quantidade de transações processadas por unidade de tempo.

**Token**
Credencial temporária usada para autenticação e autorização.

**Timeout**
Tempo limite máximo para uma operação ser concluída.

---

## U

**Unit Testing**
Testes que validam componentes individuais isoladamente.

**User Story**
Descrição breve de uma funcionalidade do ponto de vista do usuário.

**UUID (Universally Unique Identifier)**
Identificador único universal de 128 bits.

---

## V

**Validation**
Processo de verificação se dados atendem aos critérios definidos.

**VADER**
Heurística específica para testes de APIs REST (Verbs, Authorization, Data, Errors, Responsiveness).

**Version Control**
Sistema para gerenciar diferentes versões de código fonte (Git).

---

## W

**Webhook**
Método de comunicação entre sistemas através de callbacks HTTP.

**Workflow**
Sequência de passos ou atividades em um processo.

---

## X

**XSS (Cross-Site Scripting)**
Vulnerabilidade que permite injeção de scripts maliciosos em páginas web.

**XML**
Formato de marcação para estruturar e transportar dados.

---

## Termos Específicos do Projeto

### Perfis de Usuário

**Admin (Administrador)**
Perfil com acesso total ao sistema, pode gerenciar usuários, medicamentos e configurações.

**Pharmacist (Farmacêutico)**
Perfil com acesso a medicamentos, estoque e pacientes, mas sem gerenciamento de usuários.

**User (Usuário Comum)**
Perfil com acesso limitado apenas à consulta de medicamentos públicos.

### Módulos da API

**Authentication Module**
Módulo responsável por login, registro e gestão de perfis de usuário.

**Users Module**
Módulo para gerenciamento CRUD de usuários do sistema.

**Medicines Module**
Módulo para cadastro e controle de medicamentos.

**Stock Module**
Módulo para controle de entrada e saída de medicamentos do estoque.

**Patients Module**
Módulo para cadastro e gestão de pacientes.

**Reports Module**
Módulo para geração de relatórios e dashboards.

### Termos de Farmácia

**Lote (Batch)**
Identificação de um conjunto de medicamentos produzidos nas mesmas condições.

**Validade (Expiry Date)**
Data limite para uso seguro de um medicamento.

**Dispensação**
Ato de fornecer medicamentos aos pacientes.

**Estoque Mínimo**
Quantidade mínima que deve ser mantida em estoque para evitar desabastecimento.

## Códigos de Status HTTP Importantes

| Código | Nome | Significado | Uso no Projeto |
|---------|------|-------------|----------------|
| **200** | OK | Requisição bem-sucedida | GET, PUT bem-sucedidos |
| **201** | Created | Recurso criado com sucesso | POST bem-sucedido |
| **204** | No Content | Sucesso sem conteúdo de resposta | DELETE bem-sucedido |
| **400** | Bad Request | Dados inválidos na requisição | Validação falhou |
| **401** | Unauthorized | Credenciais inválidas | Login falhou, token inválido |
| **403** | Forbidden | Acesso negado | Sem permissão para recurso |
| **404** | Not Found | Recurso não encontrado | ID inexistente |
| **409** | Conflict | Conflito com estado atual | Email/código duplicado |
| **422** | Unprocessable Entity | Dados válidos mas não processáveis | Regra de negócio violada |
| **429** | Too Many Requests | Rate limit excedido | Muitas requisições |
| **500** | Internal Server Error | Erro interno do servidor | Bug no sistema |

## Padrões de Nomenclatura

### Casos de Teste
```
TC-XXX: [Módulo] - [Ação] - [Cenário]
Exemplo: TC-001: Authentication - Login - Admin Válido
```

### Bugs
```
BUG-XXX: [Módulo] - [Problema Resumido]
Exemplo: BUG-001: Authentication - Token não expira corretamente
```

### Branches Git
```
feature/[modulo]-[funcionalidade]
bugfix/[bug-id]-[descricao]
test/[versao]-[modulo]
```

### Variáveis de Ambiente
```
[CONTEXTO]_[COMPONENTE]_[PROPRIEDADE]
Exemplo: TEST_ADMIN_EMAIL, API_BASE_URL
```

## Convenções de Código

### JavaScript/Node.js
- **camelCase** para variáveis e funções
- **PascalCase** para classes
- **UPPER_SNAKE_CASE** para constantes
- **kebab-case** para arquivos e URLs

### Arquivos de Documentação
- **kebab-case** para nomes de arquivos
- **snake_case** para variáveis em YAML
- **camelCase** para propriedades JSON

## Ferramentas Específicas

### Mocha Hooks
- **before()** - Executado uma vez antes de todos os testes
- **after()** - Executado uma vez após todos os testes  
- **beforeEach()** - Executado antes de cada teste
- **afterEach()** - Executado após cada teste

### Chai Assertions
- **expect().to.be.true** - Verifica se é verdadeiro
- **expect().to.have.property()** - Verifica propriedade
- **expect().to.equal()** - Comparação de igualdade
- **expect().to.be.a()** - Verifica tipo de dados

### k6 Métricas
- **http_req_duration** - Tempo de resposta HTTP
- **http_req_failed** - Taxa de falha das requisições
- **http_reqs** - Total de requisições HTTP
- **vus** - Usuários virtuais simultâneos
